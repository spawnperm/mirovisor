# ADR-001: Schema-per-Tenant Multi-Tenancy Isolation with PostgreSQL RLS

## Статус
Принято (Accepted)

## Контекст
Платформа МИРОВИЗОР обслуживает независимых тенантов (холдинги, дочерние предприятия, команды).
Требуется гарантировать:
1. Полную изоляцию данных и предотвращение утечек между тенантами (Data Leak Prevention).
2. Защиту от случайного выполнения запросов без указания идентификатора тенанта (OWASP ASVS 5.0 L2).
3. Возможность индивидуального бэкапа и миграции схемы для ключевых тенантов.

## Решение
Использовать гибридный паттерн:
- **Schema-per-Tenant**: каждый тенант получает отдельную схему в PostgreSQL (`tenant_{tenant_id}`).
- **FORCE ROW LEVEL SECURITY (RLS)**: на уровне каждой таблицы активируется принудительная RLS-политика, связывающая `tenant_id` с сессионной переменной PostgreSQL `app.current_tenant_id`.
- Общий системный каталог тенантов и метаданных хранится в защищенной схеме `platform_registry`.

## Последствия
- Положительные: Аппаратная защита ядра СУБД от cross-tenant атак, простое удаление/архивирование тенанта через `DROP SCHEMA ... CASCADE`.
- Ограничения: Требуется контроль количества схем (рекомендуется до 10,000 схем на один кластер PostgreSQL).
