# Политика безопасности (Security Policy) Mirovisor

## ⚠️ Срочное уведомление о компрометации токенов (High-Priority Alert)
Если в историю коммитов, чат или логи случайно попал персональный токен GitHub (PAT) или секретные ключи:
1. **Немедленно отзовите скомпрометированный токен**: 
   - Перейдите в [GitHub Settings → Developer Settings → Personal Access Tokens](https://github.com/settings/tokens) и нажмите **Revoke/Delete**.
2. **Сгенерируйте новый токен** с минимально необходимым набором разрешений (Least Privilege) и ограничением по сроку действия (Expiration $\le 30$ дней).
3. **Установите pre-commit хук Gitleaks**:
   ```bash
   brew install gitleaks
   gitleaks protect --staged
   ```
4. **Никогда не передавайте токены в открытом виде** в командных чатах, логах или промптах.

## Стандарты безопасности Mirovisor
Платформа спроектирована с соблюдением требований **OWASP ASVS 5.0 Level 2**:

1. **Изоляция данных (Schema-per-Tenant)**:
   - Каждый тенант располагает выделенной схемой PostgreSQL (`tenant_{id}`).
   - Принудительное включение `FORCE ROW LEVEL SECURITY`.
   - Санитизация `tenant_id` перед `SET search_path` (только regex `^[a-z0-9_-]{3,32}$`).

2. **Защита API и AI-агентов**:
   - Никаких API-ключей (включая Gemini / OpenAI) на стороне клиентского браузера.
   - Все запросы к LLM и внешним сервисам маршрутизируются через серверный шлюз с валидацией сессии и rate-limiting.

3. **Совместная работа (Yjs WebRTC)**:
   - Аутентификация комнат на базе эфемерных JWT-токенов с привязкой к `tenant_id` и `user_id`.
   - Защита от подделки awareness/presence данных.

4. **Сообщение об уязвимостях**:
   При обнаружении уязвимости направляйте детали на `security@mirovisor.internal` или создайте конфиденциальный отчет (Advisory) в GitHub.
